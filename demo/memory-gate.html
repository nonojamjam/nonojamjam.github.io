Verify, remember, compute less

A 2-link arm reaches clustered targets. A planner proposes each move; a forward-kinematics gate checks it before execution; moves that passed are remembered and replayed in similar situations instead of calling the planner again. Toggle each part and watch the planner calls, unsafe moves and success change. Everything is computed live in your browser; the planner is a simple stand-in, not an LLM. What this is and is not. The planner here is a small analytic stand-in with injected mistakes (a wrong move 30, 50 or 70% of the time — the memory saves more when the planner is less reliable), not an LLM, so the numbers on this page are illustrative. The pre-registered runs with real LLM planners (GPT-6.1 Pro, Gemini 2.5 Flash) — e.g. 60 → 24 planner calls on the 2-link arm at 30/30 success — and their raw data are on the main page. The arm, gate, memory key and replay rule follow the same definitions as those runs, with two differences made for clarity: after four rejected proposals the arm holds still (in the runs the last proposal was executed), and with the gate switched off the memory stores moves without checking them.
